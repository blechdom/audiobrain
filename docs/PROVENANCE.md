# Source provenance

AudioBrain is an independent application in this repository. Production code does not import sibling checkouts at runtime.

| Area | Source and adaptation |
| --- | --- |
| Graph contracts and three starter instruments | The AudioBrain pre-build boundary inventory, contract proposal and draft catalog supplied the initial 20 operator identities and presets. `contracts/operator-catalog.json` promotes those definitions into the authoritative production catalog and appends standard audio/control/device operators. The three fixtures now use the production `audiobrain.project` schema. |
| Graph importer and compiler | Architecture and algorithms adapted from VideoBrain commit `b7af64b1c1615eb521209b480856bff95b33a71f`, especially `src/graph/model.ts`, `compiler.ts`, and `types.ts`: registry-derived validation, stable identities, bounded imports, typed cables, topological planning, demand reachability, and saved literals beneath live modulation. AudioBrain adds its own signal families, explicit output/view/monitor/adapter roots, separate performance layout and binding validation. |
| Project store and persistence | Architecture and algorithms adapted from the same VideoBrain commit, `src/store/projectStore.ts` and persistence helpers: Zustand state, serializable project ownership, bounded undo history, gesture grouping, transactional commands, versioned debounced local storage, and observable storage failures. Runtime/device objects remain outside project state. |
| UI and publishing foundation | The application follows the same VideoBrain source snapshot's design system and React/TypeScript/Vite/React Flow/Zustand tooling. Repository-specific AWS resource identities remain explicit. See `docs/DEPLOYMENT.md` for deployment details. |

The graph and store implementation are TypeScript adaptations for AudioBrain, not a copied VideoBrain graph format. Matching schema numbers do not make the applications' project documents interchangeable. Their separate document discriminators are validated on import.

Morphazoid runtime source provenance and licensing are recorded in `src/instruments/morphazoid/README.md`, `provenance.json`, and the adjacent `LICENSE`. Four pure modules come from Morphazoid commit `81d3530e80403976880f7161555820496c4e382e`: `geometry.js`, `l-system.js`, `graph-delay.js`, and `graph-instruments.js`. The only vendor edit removes a browser cache query from the local graph module import; original source-byte SHA-256 hashes are retained.

| Runtime boundary | Implemented adaptation and limits |
| --- | --- |
| Shapes | Uses canonical 2D contour construction, point/line/radar intersections and directed corner-envelope profiles, with 1–12 independently positioned/directed heads, mixed readers, scan axes, loop/ping-pong, rotation, stretch/skew and 1–32 sides (including circle/open line). New defaults use zero curvature. Source contour-bounds pitch and legacy centered pitch are explicit mappings. Notes and FM-kit Triggers are scheduled from source-style region entries on a 256 Hz grid; Synth retains sustained voices. Per-head drag, source-style scrubbing/rotation, translation, keyboard controls and pinned performance controls share graph parameters. Stars, 3D/4D, Rattlesnake, PM/Shepard and complete timbral parity remain tracked requirements. |
| L-Systems | Uses canonical symbol expansion, turtle trace, synchronous branch frontier, cumulative-turn frequency conversion, and square-root branch power sharing. Encounters are projected from cumulative path distance into scheduled note times. Final-iteration playback is supported; together/canon iteration modes and the original microphone branch processor are separate later adapters. Symbols are capped at 12,000, branches at 1,024, visual heads at 64, and each event batch at 256. |
| Graphs | Uses canonical seeded DAG generation, degree-normalized propagation, bounded route scheduling, cumulative route turns, and the canonical Graph Synth voice-description mapper with continuous tuning. Authored layer controls rearrange the canonical graph's points while preserving directed edges/IDs/degrees. The first topology supports layered DAGs, up to 64 vertices. Each root pulse admits at most 256 arrivals with an 8-second horizon. Graph Delay's audio-processing algorithm is not represented by these note events. |
| Audio | Native sustained sine/FM voices, separate source Shapes note attacks and actual source FM-drum synthesis share one host AudioContext. The drum adapter retains the 16-voice bank, family waveforms, pitch sweeps, modulation, tone filters, noise and clap impulses. Source Shapes Notes use 4 ms attack, contact-group duration and a 0.68 simultaneous peak-sum limit. Mode changes release the previous mode's voices and queued transients without disarming audio. Native gain/filter/delay/pan/oscillator/microphone/output/meters follow graph cables; 32 voices per bank and 96 total bound resources. This does not copy Morphazoid's full voice worklet or establish human-perceived timbral equivalence. |
| Timing and lifecycle | A 25 ms host timer schedules a 100 ms lookahead onto `AudioContext.currentTime`; animation frames do not schedule sound. Transport continues with audio off. Explicit Audio arming is separate from Play. Preset switches retain an existing arm/play state, reset the traversal epoch, and release old notes; they never auto-arm an unarmed host. Parameter edits retain resources and reader phase. Rewires gate the output during a short resource transaction. Incomplete destructive edits silence old routes; invalid non-destructive edits preserve the last valid evaluation. Browser background throttling remains a timer-scheduler limitation. |
| MIDI and input | Explicit MIDI enable installs device/channel-scoped input listeners. Held notes have explicit releases; input controls obey wired parameter precedence. Hardware output requires a session-selected output port and explicit graph route; stopping/reset/disposal clears scheduled output and owned MIDI channels. Microphone permission is separate from Audio and attaches to explicit input nodes. No device permission is requested by importing a project. |

The unit suite checks dataflow, source-derived mathematical identity, half-open event intervals, bounds, parameter wiring, lifecycle, MIDI ownership, and stale-event dropping. `e2e/audio-offline.spec.ts` additionally renders real Chromium `OfflineAudioContext` samples from all three flows, asserts finite/bounded non-silence, measures the effect of the gain node, and proves that removing the output route produces exact silence. These are mechanical checks, not a human listening or controller-feel assessment.

Nested reusable graph modules remain an extension milestone. The instrument presets expose their editable domain graphs; the application does not yet serialize opaque or nested macro instances.

## Shapes preservation follow-up

The [feature ledger](FEATURE_PARITY.md) distinguishes implemented controls, hidden/unpinned controls and still-missing source behavior. Its frozen inventory includes source-file fingerprints and the exact source revision. New node/preset defaults do not overwrite authored curvature, gain or head state in imported/saved projects.

`src/instruments/shapes-readers.test.ts` compares canonical reader fixtures, exact seams, ping-pong turns, shape bounds and control relationships. `shapesMusic.test.ts` checks source note timing/normalization and drum mappings. `e2e/shapes-playheads.spec.ts` exercises all readers, independent heads, retained offsets, full head count, touch layouts and mouse gestures. The offline audio suite renders real samples for each preset and distinguishes sustained synth, note and drum output, including mode-change release. These checks establish the specific mechanical behaviors they assert; listening and physical-controller acceptance remain unperformed.

Audit correction: integrated `shapes.html`/`combo-app.js` has a fixed directed-corner envelope. The editable ADSR/amplitude presets referenced by the earlier design notes belong to the separate legacy `shape.html`/`app.js`. Both behaviors remain explicitly inventoried; the newer port does not quietly turn the legacy editor into a completed feature.
