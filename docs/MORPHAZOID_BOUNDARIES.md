# Morphazoid instrument boundaries for Audiobrain

Status: source audit and extraction design, 2026-09-10. Version 0.1 now implements three playable presets using a subset of these boundaries; [provenance](PROVENANCE.md) records the exact retained behavior and limits. This source inventory remains the broader extraction target. Importing an arbitrary existing Morphazoid page does not produce an AudioBrain node.

The useful abstraction is **a playable instrument with inspectable parts**. Preserve each instrument's characteristic connection between gesture, visible mechanism, and sound. Offer that instrument as one node, and let an author enter its subgraph to replace a reader, mapping, voice, or output. A shared parameter model connects the graph editor, MIDI/OSC mappings, automation, and performance views. None of those input sources should have to manipulate another view's DOM controls.

Source links below point to the fixed audited Morphazoid GitHub revision. They record the code inspected, including implementation limitations. Proposed boundaries use the [contract design](CONTRACTS.md); the original standalone apps do not expose these wire types. AudioBrain now implements **Morphazoid Shapes**, **Morphazoid L-Systems**, and **Morphazoid Graphs** as production presets. The source-preserving variants later in this document have distinct names and defaults.

Expose independent nodes after the coarse instrument matches source behavior; no separate fork of its math is needed.

## Proposed contract conventions

The [contract design](CONTRACTS.md#signal-families) own the vocabulary: Videobrain-aligned `control.f32`, `event.trigger`, `audio.block`, and `audio.spectrum`, together with `text.utf8`, `transport.state`, `geometry.path`, `geometry.graph`, `geometry.features`, `event.feature`, `music.voices`, and `event.note`. These are semantic boundaries, not a requirement to copy PCM or complete geometry through JSON on every frame. The [production catalog](../contracts/operator-catalog.json) defines the currently implemented signal/operator subset; fuller source-preserving adapters require additional declared fields and conformance work.

| Concern | Proposed rule |
| --- | --- |
| Scalar meaning | `control.f32` has declared unit/range/default/interpolation: Hz, linear gain, seconds, radians, cycles, or normalized value. Audio gain, display normalization, and MIDI velocity are distinct mappings. No silent unit conversion. |
| Numeric modulation | A scalar lane targets one parameter. `music.voices` carries bounded continuous polyphonic targets with stable voice IDs, activity, frequency, amplitude, pan, timbre and interpolation policy; never place a polyphonic array inside `control.f32`. |
| Events | `event.trigger` carries an event/source ID, epoch, timestamp and normalized strength for clock/manual pulses. `event.feature` carries registered geometric fields required by a mapping. `event.note` has explicit on/off/expression variants with source-scoped note identity; score durations compile into matching on/off events. Raw MIDI bytes use `event.midi`. |
| Geometry | Preserve IDs, dimension/coordinate space, bounds, version/revision, and mathematical metadata required by a reader. Initial L-System branches use `geometry.path` with parent/branch/length/turn metadata; directed node/edge topology uses `geometry.graph`. `geometry.features` carries continuous observations; `event.feature` carries discrete encounters. Producer/consumer required-field declarations prevent superficially matching type names from hiding missing measurements. |
| Scheduling | Host owns transport and audio time. Every event has an explicit time domain; convert beats at one clock boundary. Musical events are scheduled ahead against the audio clock, while rendering samples an observable state. |
| Audio | `audio.block` describes an audio-rate connection with sample rate and channel layout. Use direct Web Audio/AudioWorklet connections in the local runtime; a cross-process transport needs a separate buffering/latency contract. |
| Analysis | `audio.spectrum` includes transform size, sample rate, bin/band frequencies, amplitude scale, and timestamp. RMS, peak, centroid, or a selected band become named scalar extraction outputs when connected to control mappings. |
| UI | A performance view is a registry entry mounted against node state and subscribed outputs. Persist its kind, node/parameter binding, position/size, and presentation settings. DOM, Canvas, React elements, AudioNodes, and closures are not graph-wire payloads. |
| State | Authored parameters/seed and performance layout are persistent. Audio arming, device permission, held notes, timers, AudioContexts, worklet buffers, and momentary meter history are runtime state. A patch load starts audio off. |
| Mutations | Commit coherent graph/parameter revisions. Ordinary parameter edits preserve phase and audio history; a topology edit has an explicit bounded transition. UI refresh does not recreate engines. |
| Extensions | Register type/port/schema version, supported execution backend, parameter/view manifest, resource budgets, migration, and lifecycle. Unknown required extensions produce a readable unsupported-node state while preserving the document. |

## Migration constraints and acceptance evidence

1. **Fix the clock boundary while extracting.** Shapes already has a persistent fixed-grid lookahead scheduler anchored to `AudioContext.currentTime`, stale-attack dropping, and deterministic rate limits. [combo-app.js:696](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/combo-app.js#L696). L-Systems currently advances note/trigger traversal from `requestAnimationFrame` and calls strike/trigger without a scheduled `startAt`. [l-systems-app.js:1240](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/l-systems-app.js#L1240), [1131](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/l-systems-app.js#L1131). Graphs schedules against audio time with lookahead, but calls that scheduling from its frame loop. [graph-instrument-app.js:950](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/src/graph-instrument-app.js#L950), [1259](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/src/graph-instrument-app.js#L1259). The existing applications do not already provide one reusable production graph clock.

2. **Preserve explicit Audio versus transport.** Audio can be off while simulation and performance UI run. Device/MIDI enable paths need explicit contracts. Follow the source [audio/transport contract](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/contracts/audio-transport-v1.md) and [MIDI contract](https://github.com/blechdom/morphazoid/blob/81d3530e80403976880f7161555820496c4e382e/contracts/web-midi-toolbar-v1.md), while resolving code/contract discrepancies during adaptation rather than copying them. Shapes' current MIDI handler arms audio for notes/start; that behavior should become a documented opt-in mapping, not an accidental graph side effect.

3. **Separate authored state, runtime state, and view layout.** Preset loads, topology updates, undo, and opening a second view must not recreate contexts or reset phase unnecessarily. Define note-off/panic, cancellation of future events, voice retirement, and live-buffer transition rules. Preserve source URLs/local banks in Morphazoid; add explicit importers rather than rewriting the old applications.

4. **Bound each layer independently.** L-system symbol expansion, graph queue admission, geometric contact samples, active voices, GPU buffers, background-worker traffic, visual vertices, and outgoing device events require budgets. Source Graphs already reserves reachability before duplicate paths can consume the whole queue; preserve that fairness.

5. **Make data egress real and explicit.** A numeric monitor or a MIDI preview is not routed hardware output. The source MIDI toolbar documents preview-only paths for some pages. Define explicit route selection, conversion, timestamps and panic. OSC transport belongs to an I/O adapter with capability reporting; no audited flow establishes an existing reusable OSC endpoint.

6. **Retain the performance instrument.** A preset acceptance pass should compare geometry/contact or branch identity, attack times, pitch/pan/gain relationships, silence/release, preset transitions and cleanup. Test that UI frames can pause while scheduled audio continues as designed. Test both coarse and entered versions against the same fixture. Numerical tests do not establish matching timbre or gesture feel; those require an audible and human performance pass.

7. **Keep outputs honest.** Multichannel output must inspect actual device capacity and label a stereo preview/downmix. Browser microphone permission and device selection belong to the host. A remote Videobrain connection should send declared controls/events/analysis first; local audio routing and remote audio streaming have different latency and transport needs.

This audit changed no Morphazoid source or generated artifacts. Its checkout contained unrelated staged Puggler work, which was left untouched.
